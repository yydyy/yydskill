### 3.3 建议：不要全量翻译

1,600 万字符全量翻译约 240 万字，成本远超收益，而且 `03-技术栈参考` 本身**从不自动部署**（README 明确"不要整包同步进项目"）。三个分层方案：

**第一层（必译，量很小）：**
- `02-个人习惯` 5 个 `SKILL.md` —— **已经是中文**，无需处理
- `01-工程原则` 60 个文件 —— **已经是中文**，只需核对 YAML `name` 是英文
- 即：真正天天加载的 68 个文件**本来就全是中文**。这层已完成 ✅

**第二层（值得译，中等量）：**
- `03-技术栈参考/目录.md` 里的中文名目前是"英文标题机器直译"（如 `SvelteKit restful api Tailwind css`、`cursor ai React TypeScript shadcn ui cursorrules p`），**可读性很差**，应改写成真正的技术栈中文名，例如：
  - `cursor ai React TypeScript shadcn ui cursorrules p` → **React + TS + shadcn/ui 组件开发规范**
  - `typescript-zod-tailwind-nextjs-cursorrules-prompt-` → **Next.js + Zod + Tailwind 类型校验规范**
  - `knative-istio-typesense-gpu-cursorrules-prompt-fil` → **Knative + Istio + Typesense GPU 部署规范**
- 242 行目录，投入产出比最高的一项。

**第三层（按需译，不要预译）：**
- 178 个包正文：**用到哪个译哪个**。做法：在包内加一份 `摘要.md`（中文，5–10 条要点），原文保留英文。这样单包翻译量从 8 KB 降到 1 KB 左右，且只译你真正会用的（按你的栈估算约 15–25 个包，合计约 **25–40 KB 中文**，而非 1.6 MB）。

### 3.4 顺带：翻译前先解决重复，否则等于重复翻译

`03` 区 56 对高重合包 + 135 个双格式包意味着：**现在动手翻译，Next.js 那一族要把同一批规则译 13 遍，Python/FastAPI 译 5 遍，Cypress/Playwright 译 10 遍。** 正确顺序是 **先合并去重，再翻译**。
