# 英文文件名含义

> `03-技术栈参考/原规则/规则包` 里 1019 个 `.mdc` 等文件的**文件名保持英文**（改名会牵动引用，且规则生效靠文件里的 `globs` 与文件名无关）。
> 本文分两部分：先讲**命名规律**（看名字猜主题），再给**逐包文件名 → 中文含义对照表**。
> 136 份 `README.md` 是包说明，**已全部译成中文**（原文备份：`D:\Documents\AI技能库-README原文备份-*.zip`）。

## 一、命名规律

1. **kebab-case 全小写**：单词之间用 `-` 连接，例如 `error-handling-rules.mdc`。
2. **`---` 是「技术栈 --- 主题」分隔符**：上游包目录名常带 `-cursorrules-prompt-file` 后缀，拆文件时用 `---` 把技术栈前缀和主题分开，例如 `android-jetpack-compose---performance-guidelines.mdc` = Jetpack Compose 的性能指南。
3. **结尾词决定文件类型**：
   - `*-rules.mdc` / `*-rule.mdc`：某主题的规则集
   - `*-guidelines.mdc`：指南（偏建议性）
   - `*-best-practices.mdc`：最佳实践
   - `*-conventions.mdc`：约定（命名/风格/目录）
   - `*-instructions.mdc`：给 Agent 的补充指示
4. **`general-*` 是总纲**：`general-coding-rules.mdc` 通用编码规则；同包里 `general-*` 通常先读。
5. **与包同名的 `.mdc` 是主文件**：例如 `Python FastAPI 最佳实践/python-fastapi-best-practices.mdc`，一般是整包入口/角色定义。
6. **固定名字**：`README.md` = 上游包说明（已中译）；`补充原文.md` = 清理时抽出的孤立规则原文（中文）；`SKILL.md` = skill 正文（只在 01/02 出现）；`完整版.md` / `极简版.md` = 工程原则的长短两版。
