# Playwright 缺陷追踪提示词

一个专门的 .cursorrules 提示词，用于使用 Playwright 配合 TypeScript 和用例 ID 标签创建全面的缺陷复现与追踪测试。

## 你可以构建什么

- **缺陷复现测试**：能可靠复现已报告缺陷的精确测试用例
- **回归测试套件**：验证已修复的缺陷在后续版本中不再出现的测试
- **用例 ID 关联测试**：通过 ID 标签与手工测试用例直接关联的测试
- **分类测试套件**：带有恰当类别与团队标签、组织良好的测试
- **基于证据的报告**：内置证据收集与报告能力的测试运行
- **结构化测试层级**：按功能和团队进行逻辑组织的测试结构

## 优势

- **手工到自动化的可追溯性**：手工测试用例与自动化测试之间的清晰映射
- **有组织的测试结构**：按功能和类别对测试进行逻辑分组
- **完整的 TypeScript 支持**：缺陷追踪测试代码具备完整的类型安全
- **精简的报告流程**：内置对生成详细测试报告的支持
- **团队归属明确**：清晰标明每个测试套件所属的团队
- **按类别执行**：可按类别（smoke、regression 等）运行测试
- **全面的证据**：为缺陷文档自动生成截图和日志

## 简介

本提示词帮助 QA 团队使用 Playwright 配合用例 ID 标签创建全面的缺陷追踪与复现测试。它聚焦于有逻辑地组织测试、保持与手工测试用例的可追溯性，并生成用于缺陷追踪的结构化报告。

## .cursorrules 提示词概述

.cursorrules 提示词指导 QA 工程师使用 Playwright 创建有效的缺陷追踪测试，关键要素包括：

- **TypeScript 检测**：自动检测并适配项目中 TypeScript 的使用
- **用例 ID 标签**：在方括号中包含手工测试用例 ID（[C1234]）的框架
- **测试类别**：将测试标记为 [smoke]、[regression]、[defect] 等的分类体系
- **团队归属**：用团队名标签标明测试所属团队的方法
- **配置示例**：QA shadow 报告系统的示例配置文件
- **测试模式示例**：带正确 ID 标签的缺陷追踪测试详细示例
- **结构化组织**：按逻辑层级组织测试的指南
- **最佳实践**：有效缺陷追踪与报告的八项核心实践
