# GitHub .cursorrules 提示文件说明（GitHub .cursorrules prompt file instructions）

作者：Jeremy Russell

## 你可以构建什么（What You Can Build）
代码可读性与可维护性分析器：一款检查现有代码库并就可读性和可维护性提供反馈的工具，高亮复杂逻辑、硬编码数字、描述不清的变量名等可改进之处。变量命名建议工具：一款根据上下文和用法为变量、函数和类建议有意义、描述性名称的应用，帮助开发者编写自文档化的代码。DRY 原则检查器：一项扫描代码库找出重复代码并建议重构方式以遵循"不要重复自己（DRY）"原则的服务。嵌套条件重构工具：一款检测嵌套条件语句并建议将其封装为独立函数以提升可读性和可维护性的工具。注释质量分析器：一款分析代码注释、识别无用或过时注释并为有意义的注释提出改进建议的应用。持续重构支持工具：一款集成开发工具，在开发者编写和修改代码时持续反馈可重构的潜在区域。编码标准执行器：一款插件或服务，自动按特定语言既定的编码标准和规范检查代码，即时向开发者反馈。版本控制最佳实践指南：一个提供版本控制系统使用最佳实践指导和教程的在线资源或工具，尤其面向协作和重构项目。函数复杂度最小化工具：一款把过于复杂的函数拆分为更小的单一职责函数的工具，让开发者更易维护代码。代码风格指南生成器：一项帮助团队根据自身独特需求、同时遵循通用语言约定创建定制编码风格指南的服务。

## 简要说明（Synopsis）
软件开发者可以使用这份提示，通过实践整洁代码来提升代码质量，增强项目中的可读性、可维护性和团队协作。

## .cursorrules 提示内容概述（Overview of .cursorrules prompt）
.cursorrules 文件讨论了编写整洁、可读、可维护代码的重要性。它概述了 Robert Cecil Martin 定义的"整洁代码（clean code）"概念，并说明其在提升代码可读性、可维护性、团队协作、调试和代码质量方面的意义。文件详述了实现整洁代码的最佳实践和原则，包括使用命名常量、有意义的名称、少而精的注释、遵循单一职责原则的短函数、避免代码重复、遵循编码标准、封装嵌套条件、持续重构以及使用版本控制系统。这些指南旨在帮助开发者创建更高效、更可靠、更易懂的软件。
