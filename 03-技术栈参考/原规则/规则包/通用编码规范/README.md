## 你可以构建什么
代码分析工具：开发分析代码是否符合 .cursorrules AI 文件所定规则的工具，高亮诸如缺失错误处理、测试覆盖不足、编码风格不符等违规项。自动化重构服务：创建逐文件自动重构代码的服务，遵循不建议空白字符改动、避免魔法数字、确保模块化设计等准则。项目一致性检查器：构建检查项目中多个文件的编码风格、性能优先级和安全考量是否一致的工具，同时避免不必要的更新。开发者助手扩展：设计浏览器或 IDE 扩展，对代码编辑实时反馈，强调显式变量命名、避免道歉、无需多余确认。代码优化平台：搭建平台，在确保版本兼容、坚持安全优先的同时，提出性能改进和模块化设计策略。单元测试建议应用：为新增或修改的代码自动生成单元测试，强调覆盖率，除非被要求，否则不展示或讨论当前实现。版本兼容性分析器：检查代码变更是否与项目指定的语言或框架版本兼容，确保集成与功能顺畅。边界用例识别器：扫描代码识别潜在边界情况并给出处理策略，确保稳健的错误处理与日志记录。上下文感知代码审查器：利用生成的上下文文件对编辑给出反馈的代码审查平台，确保无多余确认并保留文件。模块化设计教学平台：教育开发者实现并践行模块化设计原则的学习平台，聚焦代码的可复用性与可维护性。断言校验器：集成到 CI/CD 流水线的服务，检查代码中是否存在断言并被正确使用，提升校验准确性和错误的早期发现。硬编码值检测器：扫描代码库中的魔法数字并建议用命名常量替代的工具，提升清晰度与可维护性。错误处理增强器：建议改进代码中错误处理机制的插件或独立工具，提供稳健日志实践的建议。

## 简介
在协作项目中工作的开发者可以通过建立清晰高效的代码评审与更新规范，确保团队代码质量一致、安全、易维护，从而受益。

## .cursorrules 提示词概述
.cursorrules 文件列出了一套在编辑代码或提出修改建议时应遵循的规则与准则。它强调核实信息、逐文件修改、保留现有代码，避免不必要的确认或更新。文件建议不要道歉、不要做无谓的空白字符改动、也不要总结所做的修改。重点还包括提供真实的文件链接、使用显式变量命名、遵循一致的编码风格。性能、安全、错误处理、模块化设计、版本兼容、边界情况和测试覆盖被列为优先事项。文件不鼓励使用"魔法数字"，并鼓励使用断言来尽早捕获错误。
