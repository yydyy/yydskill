# Cypress 缺陷追踪 .cursorrules 提示文件

作者：Peter M Souza Jr

## 你可以构建什么

分层测试组织：创建结构最优的测试套件，采用分层打标签方式——团队名称与通用分类放在 describe/context 层级，而具体变体与用例 ID 放在单个测试层级，从而得到更干净、更易维护的测试代码。团队专属测试套件：创建自动带有团队名称、测试类型与测试分类标签的定制测试套件，使其立即兼容报告系统与筛选器。输入你的团队名称与期望的测试类型，即可生成结构正确的测试。自定义测试分类：生成带有特定分类标签（smoke、regression、usability 等）的测试，与你的测试策略保持一致，并可在报告中筛选，提升可见性与管理效率。Shadow 报告框架：构建一个精简框架，按团队与测试类型自动生成分类的测试报告，几乎无需配置。报告可分享给利益相关者，让他们了解测试覆盖与质量。Google Sheets 集成：创建自动化的报告方案，将测试结果导出到 Google Sheets，让非技术利益相关者也能轻松获取测试数据，并支持对测试覆盖与质量趋势做自定义分析。

## 优势

高效的分层打标签：在 describe 层级应用通用标签（团队、测试类型、分类），而单个测试的标签仅用于具体变体，让测试更干净、更易维护。自定义团队与分类标签：可直接输入团队名称、测试类型与分类，生成符合组织结构、标签恰当的测试。标准化测试格式：以一致方式为测试打上 ID、分类与团队信息标签，提升组织性与可检索性。TypeScript 自动检测：自动识别 TypeScript 项目并相应调整测试代码语法，无需手动配置即可获得类型安全。配置化报告：生成包含你自定义团队名称、测试类型与分类的配置文件，实现无缝报告生成。

## 简介

本提示帮助 QA 工程师为 qa-shadow-report 包创建团队专属、带分类与恰当分层标签的 Cypress 测试，实现优化的测试组织与报告。

## .cursorrules 提示文件概述

.cursorrules 文件为使用 Cypress 实施缺陷追踪与测试报告的 QA 工程师提供指导。它聚焦使用 qa-shadow-report 包与分层打标签方法：通用标签（团队、测试类型、分类）应用在 describe/context 层级，而用例 ID 与具体分类变体应用在单个测试层级，从而得到更干净、更易维护的测试代码。本提示接收用户输入的团队名称、测试类型、测试分类、待测功能与用例 ID，然后生成带有恰当标签、格式正确的 Cypress 测试。它会自动检测 TypeScript 项目并相应调整语法，同时支持 JavaScript 与 TypeScript 环境。示例演示了如何在 describe 层级应用通用的 "regression" 分类，而仅对与父级分类不同的个别测试添加 "performance" 等具体分类。
