# Gherkin 风格测试提示词

一份专用的 .cursorrules 提示词，用于以 Gherkin 格式创建清晰、结构化的测试文档，让非技术干系人也能理解。

## 你可以构建什么

- **Gherkin 测试场景**：使用 Given-When-Then 格式的结构化测试文档
- **功能文档**：对应用功能的全面测试覆盖
- **便于法务审阅的测试用例**：法务和合规团队可以审阅的测试场景
- **人类可读的测试计划**：将技术测试用例转换为通俗易懂的语言
- **数据驱动的测试场景**：使用 Scenario Outline 和 Examples 表的参数化测试

## 优势

- **跨团队协作**：技术与非技术团队都能理解的测试文档
- **法律合规**：适用于法务与监管文档的结构化格式
- **以用户为中心的测试**：从用户视角编写的场景
- **清晰的测试需求**：对测试执行和结果有明确定义的预期
- **有序的测试结构**：统一的格式，包含 feature、scenario 和步骤定义
- **行为驱动开发**：在测试工作流中支持 BDD 实践

## 简介

本提示词帮助 QA 工程师创建高质量的 Gherkin 格式测试文档，弥合技术测试与业务需求之间的鸿沟，让所有干系人都能理解测试场景。

## .cursorrules 提示词概览

`.cursorrules` 提示词通过以下关键要素指导 QA 工程师编写有效的 Gherkin 文档：

- **Gherkin 语法**：有效使用 Feature、Scenario、Given、When、Then、And、But 的指南
- **最佳实践**：编写清晰有效的 Gherkin 文档的八项基本实践
- **示例结构**：包含 background、scenario 和注释的完整 feature 详细示例
- **技术转换**：将技术测试脚本转换为 Gherkin 格式的分步流程
- **简单语言**：强调使用所有干系人都能理解的非技术性语言
- **数据示例**：结合 Examples 表实现数据驱动测试的技巧
- **场景组织**：在 feature 内组织相关测试场景的方法
